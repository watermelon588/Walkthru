# MVP scope: prove one valuable mission

Assumption: willingness to pay and new model quality are not established. Scope is a proposed narrower pilot, not the whole master plan.

## Definition

A builder can test an explicitly scoped signup-to-first-value journey in their authorized browser, receive reproducible evidence and an acceptance test, then verify the fix. Runtime is measured during pilots; no arbitrary universal minute promise.

## Triage

| Feature | Category | Reason |
| --- | --- | --- |
| Reliable controller and meaningful finish evidence | Must | A failed traversal undermines the deliverable |
| Versioned scope/expected/observed dossier | Must | Makes a finding actionable and honest |
| Masked screenshots and reproduction | Must | Buyer can inspect what happened |
| Owner-defined assertions/test data | Must | Business correctness needs expectations |
| Quotes/reservations/spend controls | Must | Paid depth must not create uncapped liability |
| Targeted rerun | Must | Proves whether the purchased fix worked |
| Saved suites and cross-release history | Should | Creates repeat value after reliability |
| Scoped API/MCP | Should | Useful developer integration sharing wallet controls |
| Search Console query/page opportunities | Should | Real-data strategy, after core mission demand |
| Resource-level performance diagnosis | Should | Reuses existing measurements more effectively |
| Extra personas/roles/devices | Later | More cost; expand against demonstrated need |
| Paid keyword/SERP research | Later | Optional demand data, separately budgeted |
| Annotated evidence highlight clip | Later | Helps handovers once raw evidence is trusted |
| General model API proxy | Won't for pilot | Different product and abuse surface |
| BYO SMTP | Won't for pilot | No demonstrated customer need; transport does not buy intelligence |
| Personal inbox integration | Won't for pilot | Broad privacy/credential scope |
| Continuous recording | Won't for pilot | Permissions/masking/storage not proven |
| Hosted autonomous browser | Won't for pilot | Separate session/credential/compute problem |
| Generated visual redesigns | Won't for pilot | Could confuse suggestion with verification |
| Autonomous app repairs/backend writes | Won't for pilot | Outside current safety contract |

## Critical flow

1. Select verified project and outcome/test fixture.
2. Accept scope, actions and maximum usage price.
3. Start connected browser mission; human auth handoff when needed.
4. Read coverage, outcomes and evidence-linked issues.
5. Fix and rerun the selected assertion.

Each setup screen should be simple; execution itself is asynchronous and can take minutes. A dashboard/API request cannot create a connected authenticated browser by itself.

## Build versus reuse

Keep React/Vite, FastAPI/LangGraph, Supabase, durable jobs and extension. Reuse masking, snapshots, outcomes, comparison and fix recipes. Add only the mission/assertion/report/wallet records that are necessary. Preserve legacy reports. Browser-local test accounts remain preferable to casually collecting credentials.

Estimate: report v2 3-5 days; controller/minimal assertions 5-10; usage records/quotes/reservations 5-8; targeted retest polish 2-4. Total roughly 3-6 focused engineering weeks plus approvals, evaluation and customer pilots. These are solo-development estimates, not commitments. Broad master-plan scope is longer.

Hosting remains the previously proposed Cloudflare frontend/DNS, Google VM API/worker and Supabase; no new purchase follows from this scope. Public scans and interactive journeys have different execution environments.

## Pilot exit criteria

- Explicit scope and safe permitted actions.
- Independent reproduction from the dossier.
- No unsupported completion or stopped-run defect claims.
- Provider/controller failure distinguished from app defect.
- Wallet concurrency/replay/timeout controls pass.
- Real installed-extension acceptance.
- Owner can fix/retest one meaningful assertion.
- Actual paid interest and time saved recorded.

Optional video, branded exports and growth-review polish can wait. Misleading severity, raw private evidence, unbounded spending or unsafe actions cannot. The first ten participants test whether evidence changes a repair/release decision, not whether they admire the feature count.
